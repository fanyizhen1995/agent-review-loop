# 通用流程演进约定

公共套件演进围绕配置、工作流、forge 和适配器边界。业务路径、部署方式、术语、规则补充和登记 schema 由独立项目目录承载。

1. 明确行为与权限边界，先用虚构输入编写有意义的离线行为测试。
2. 为通用能力增加配置或契约，保留目录和单 TOML 两种入口的兼容行为。
3. 从同一 workflow 生成执行与评审要求，避免各模板分别维护验证逻辑。
4. 产品专属任务与安装格式放适配器，项目专属命令放 hook 和资源目录。
5. 验证两个虚构 forge 示例的渲染、安装预览、权限和资源复制。
6. 更新文档并运行公开内容检查，私有运行基线在独立仓库中对账。

测试结论只描述已执行的检查。远端权限、CLI、模型和部署可用性由项目自己的环境验证。
