# 公开发布检查

发布前在仓库根目录执行：

```sh
python3 install/publish_check.py --deny-file "$ARL_DENY_FILE"
```

`ARL_DENY_FILE` 应指向仓库外的私有 UTF-8 规则文件。每行是一条 Python 正则；空行及首个非空白字符为 `#` 的注释行会忽略，其余行保留原有空格。规则、凭据及真实部署信息不应提交到公开仓库。规则文件不可读或正则无效时检查失败；错误只报告规则行号，不回显规则。

检查完全离线，不执行 fetch、push 或 SSH，并禁用缺失对象的自动拉取；本地对象不完整时检查失败。检查范围包括：

- 当前工作区的文件路径和文本内容，包括未跟踪文件、被 `.gitignore` 忽略的 `build/` 产物。
- Git 索引中的暂存文件内容；HEAD 中所有仍存在于工作树的跟踪文件路径和文本内容。因此，已提交的敏感内容即使在工作树改回安全版本，仍会命中。
- `git diff origin/main..HEAD` 中的新增文件路径和新增文本行。删除行、删除文件的旧路径不进入发布内容，避免阻止移除旧敏感内容的迁移提交。被替换的旧行也不扫描。

`.git/`、`__pycache__/`、常见 Python 工具缓存目录、`.pyc`/`.pyo` 文件会跳过。含 NUL 字节或无法解码为 UTF-8 的文件按二进制跳过内容；其路径仍检查。符号链接检查链接本身的目标文本，不读取链接外的内容。子模块的 Git 链接只检查路径；已检出的子模块文件属于工作区扫描范围。

没有本地 `origin/main` 引用时，工具会明确提示“离线降级”，继续检查工作区和全部现存 HEAD 跟踪内容，不读取任意旧提交作为替代。HEAD 跟踪文件若已从工作树删除，视为待提交删除，不扫描其旧内容。尚未创建首个提交的仓库检查工作区和 Git 索引。工具不遍历历史提交；需要清除历史时另行安排历史重写。

命中时输出来源、仓库相对路径与行号，行号 `0` 表示路径命中；不输出命中文本或规则。退出码 `1` 表示命中，`2` 表示检查失败。只有完整检查通过才输出“零命中”并返回 `0`。待提交删除属于工作区计划；正式推送前应先提交清理结果，然后再次执行检查。

可安装本地推送钩子：

```sh
cp hooks/pre-push.sample .git/hooks/pre-push
chmod +x .git/hooks/pre-push
export ARL_DENY_FILE="$HOME/.config/agent-review-loop/publish-deny.txt"
```

钩子要求设置 `ARL_DENY_FILE`，未设置即阻止推送。样例仅在复制安装后生效；已有 `pre-push` 时应将检查合并到已有钩子。规则文件必须自行创建，仓库不包含真实私有词表。该钩子核查当前工作区与当前 HEAD，不根据推送参数枚举其他分支或标签；推送其他引用前应切换到对应分支执行检查。

此检查覆盖当前内容与指定分支间的净新增差异，不遍历全部历史提交。首次公开发布前还需核对既有 Git 历史；已删除的文件仍可能存在于历史对象中。
