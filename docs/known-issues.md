# 已知限制与部署检查

下列事项需要在项目接入时处理。离线测试覆盖请求构造、状态转换、权限边界与安装预览，不能证明远端权限、模型或业务部署可用。

| 范围 | 限制及处理 |
| --- | --- |
| Hermes CLI | 正式安装检查帮助与 JSON 任务列表，未知版本停止；接入时核对 create/edit 参数 |
| Hermes 多项目 | 同一 home 共用脚本和配置，不同项目拒绝覆盖；使用独立 profile/home |
| 配置合并 | 标准库实现只支持受管 YAML 的明确结构；重复键、别名、复杂嵌套需人工整理 |
| 列表探测 | 部分状态探测 API 有数量上限；大量条目时需核对分页与发现范围 |
| 评论排序 | 范围确认的排序取决于 forge 返回顺序；接入时用多次确认场景核对顺序 |
| 清理结果 | 删除命令失败后的记录需结合实际输出检查，不能仅凭汇总认为已删除 |
| GitHub App | 当前身份核对使用 `/user`，installation token 需额外身份及续期适配 |
| GitHub Rulesets | doctor 检查传统保护 API，额外 Rulesets 与豁免需另行核对 |
| GitHub token | fine-grained token 无统一到期查询接口，到期日需自行记录 |
| 复杂度 | 公共 complexity.py 面向 Python，其他语言配置 workflow.metrics 命令 |
| 分支保护 | 用户、组、团队或 App 豁免需结合实际规则核对 |
| 项目 hooks | 受信命令需要独立审查，确认资源范围、锁、凭据和失败行为 |
| Cron | 时刻使用运行主机本地时区，部署时核对时区及 PATH |

审批 deny 是命令匹配防护，文字规则依然有效。项目需要核对命名空间的短、长参数，以及分支推送的多种形式；禁止为绕过拒绝而换写命令。

自动合入需要成员可见性与合入权限，登记需要目标分支推送权限。实际账号、保护规则、模型、agent 任务系统和环境冒烟须在自己的部署环境验证。原因未查明的失败按“原因未查明”记录，不补造解释或历史同意证据。
